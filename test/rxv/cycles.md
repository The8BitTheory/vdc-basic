# RXV: cycles in VICE (preliminary)

Generated by `test/rxv/run_rxv.py --cycles F` (1 MHz) and `--fast --cycles-append F` (2 MHz). Stopwatch of the
VICE monitor from `rxv_execute` to `complex_instruction_shared_exit`, IRQ disabled for the measurement (I flag
via the monitor), minimum of 8 runs per vector (the raster position varies). The stopwatch counts
system clocks at 1 MHz: without `FAST` 1 CPU cycle per clock, with `FAST` 2; the tables show **CPU cycles**.
The CPU path (comparison with the listing, docs/v3/P2b-rxv.md 6) is in "1 MHz, R6 = 0": there the
CPU does not wait for the VDC. At 2 MHz the VDC is the limit in VICE.

**Preliminary:** VICE models VDC access in a simplified way (busy time per reg 31 access in the visible
area); the values are only good for comparing the paths with each other. Block fill rows include the
wait for the end of the fill when reading R18/R19 at the end. Values on real hardware are pending (cycle values; functional checks of RXV passed on hardware 2026-11-27).
